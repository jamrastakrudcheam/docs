# Oracle Fusion Cloud Financials: เอกสารอ้างอิงสำหรับ ICC ERP

ทิศทางที่เลือก: ทำให้ ICC ERP มี**กระบวนการและแนวคิด**แบบ Oracle Fusion Cloud Financials (GL, AP, AR, FA, Cash, Tax) โดยยังยึดข้อตัดสินใจ D/P ในเอกสาร 01 เป็นหลัก

**ที่มา:** Oracle Help Center (docs.oracle.com) รุ่น 26D ซึ่งเป็นเอกสารสาธารณะ ทุกโน้ตสรุปด้วยคำของเรา ไม่คัดลอกเนื้อหา มีลิงก์แหล่งอ้างอิงทุกข้อ และไม่ใช้ภาพ โลโก้ หรือข้อมูลที่ไม่ได้เปิดเผย

## ข้อสรุปข้ามโมดูล
1. **ทุกโมดูลลงบัญชีผ่าน SLA เข้า GL** และมีรายงานกระทบยอดโมดูลกับ GL (AP–GL, AR–GL, Cash–GL) → ตรงกับ ticket 37 และควรเพิ่มรายงานกระทบยอดใน ticket 33
2. **สถานะร่าง/สมบูรณ์ชัดเจนทุกเอกสาร** (Journal: Incomplete/Posted, AR: Incomplete/Complete, AP: Validated) ย้อนสถานะไม่ได้เมื่อพิมพ์ มีเลขแล้ว หรือลงบัญชีแล้ว
3. **อนุมัติด้วย workflow กลางที่ตั้งกฎได้** (ยอด, category, source, ผู้อนุมัติตามสายงาน) และตั้งให้ข้ามผู้สร้างได้ → ticket 03 · ของเราบังคับ maker ≠ checker เสมอ (D07)
4. **Spreadsheet import ทุกโมดูล** ใช้รูปแบบ FBDI เดียวกัน → ตัดสินแล้ว: ทำ **บริการนำเข้ากลางแบบ FBDI** (ticket 36, [import-framework.md](../import-framework.md)) และ import object ต่อโมดูล
5. **งวดของแต่ละโมดูลปิดก่อน GL** และ FA ปิดแล้วเปิดใหม่ไม่ได้
6. Fusion **ไม่มีรายงานภาษีซื้อ/ขายแบบไทยหรือ ภ.พ.30** มีเฉพาะ 50 ทวิ → ticket 39 เป็นงานออกแบบของเราเอง

## ประเด็นใหม่ที่ควรเพิ่มใน ticket 01
- ภาษีขายประเภทบริการรับรู้เมื่อรับชำระ (tax point = payment, บัญชีภาษีขายรอเรียกเก็บ) ต้องรองรับรอบแรกหรือไม่
- ภาษีซื้อต้องห้าม (recovery rate) จัดการอย่างไร
- WHT หักตอนจ่ายเงินเป็นค่าเริ่มต้น และตั้งกรมสรรพากรเป็นผู้ขายประเภทหน่วยงานภาษีหรือไม่
- ต้องนำเข้าข้อมูลยกมาจากระบบ Oracle เดิม (ยอดบัญชี, สินทรัพย์, AR/AP ค้าง) เป็น ticket แยกหรือไม่ (D01 ระบุว่าทดแทน Oracle เป็นระยะ)

## ข้อจำกัด
- อ่านเฉพาะหัวข้อหลักของแต่ละคู่มือ บางหน้าในคู่มือไม่ได้ลงรายละเอียด (เช่น ระดับ 2/3/4-way match, ประเภท queue ของ mass additions) ถ้าจะใช้หัวข้อไหนจริงควรอ่านหน้าย่อยเพิ่มตอนเริ่ม ticket นั้น
- เอกสาร localization ไทยมาจากรุ่น 24C–25D เพราะหน้ารุ่น 26D ไม่ปรากฏในผลค้นหา
