# Fusion อ้างอิง: General Ledger (GL)

อ่านจาก Oracle Help Center รุ่น 26D (สรุปด้วยคำของเรา ไม่ใช่สำเนาเอกสาร) · ใช้กับ ticket [04](../issues/04-fiscal-calendar-periods.md), [06](../issues/06-chart-of-accounts-tax.md), [12](../issues/12-gl-journal-entry-posting.md), [32](../issues/32-recurring-allocation-reversal.md), [33](../issues/33-period-year-close.md), [36](../issues/36-file-based-data-import.md), [42](../issues/42-journal-import-object.md) · แนวทางของเรา: [gl-process.md](../gl-process.md)

## ตาราง: Fusion ทำอย่างไร → เราทำอย่างไร

| หัวข้อ | Fusion | ระบบเรา | ต่าง / ต้องตัดสินใจ |
| --- | --- | --- | --- |
| โครง Journal | Batch → Journal → Line · Batch ต้องมีชื่อ, source, period · ทุก Journal ใน Batch อยู่งวดเดียวกัน · ถ้าไม่ตั้งชื่อ ระบบสร้างจาก source + id + วันที่ [1] | เหมือนกัน | ไม่มี |
| ฟิลด์ระดับ Journal | ledger, ชื่อ, accounting date, source, category, currency (บังคับ) + description, control total [1] | ledger มาจากบริษัทที่เลือก, currency = THB เสมอ (D06) | เพิ่ม **control total** (ยอดควบคุมที่กรอกเพื่อตรวจ) ได้ ควรมี |
| balance | Dr = Cr ทุก Journal ยกเว้น statistical [1] · ต้อง balance ต่อ **primary balancing segment** [5] | balance ต่อ Journal (1 Ledger = 1 บริษัท) | ถ้า COA มีหลาย balancing segment ต้อง balance ต่อ segment ด้วย (ticket 01) |
| สถานะ | Incomplete (บันทึกยังไม่เสร็จ, AutoPost ไม่เลือก) → Selected for Posting → Processing → Error / Posted · ทุกอย่างที่ยังไม่ Posted คือ Unposted [2][3] | Incomplete → Unposted → Pending approval → Ready to post → Posted / Error | ใกล้เคียง เราแยกสถานะอนุมัติเป็นขั้นในวงจรเดียว Fusion แยก approval status (Required/Approved) ออกจาก batch status → **ควรเก็บ approval status แยกฟิลด์** เหมือน Fusion |
| อนุมัติ | เปิดได้เมื่อ ledger **และ** source เปิด approval · กฎตามยอดสูงสุดต่อบรรทัด/ต่อ Journal, category, source, account, close stage · approver จากสายบังคับบัญชา/ตำแหน่ง/กลุ่ม/บุคคล · ตั้ง "ข้ามผู้สร้าง" เพื่อกันอนุมัติตัวเอง · อนุมัติทั้ง Batch · journal จาก subledger ไม่ควรเปิดอนุมัติ, allocation ไม่ผ่านอนุมัติ [5] | ผ่าน ticket 03, maker ≠ checker บังคับเสมอ (D07) | เราบังคับ SoD เสมอ ไม่เป็นตัวเลือก · journal จาก SLA ไม่ต้องอนุมัติใน GL (อนุมัติที่เอกสารต้นทาง) — ตรงกับ Fusion |
| แก้หลังอนุมัติ | แก้ได้ถ้ายังไม่ Post แต่สถานะอนุมัติกลับเป็น Required ต้องอนุมัติใหม่ [10] · ผู้ส่งถอนอนุมัติ (Withdraw) แล้วกลับเป็น Incomplete ได้ [5] | แก้แล้วกลับเป็น Incomplete และล้างการอนุมัติ | ตรงกัน · เพิ่มคำสั่ง **withdraw** |
| Post | อัปเดตตารางยอดและ balances cube · Post แล้วแก้/ลบไม่ได้ (copy หรือ reverse ได้) · post ย้อนงวดอัปเดตยอดยกมาของงวดถัดไปทั้งหมด แม้งวดปิดแล้ว · post ย้อนปีปรับกำไรสะสม · มี AutoPost ตามเกณฑ์ [6] | ตารางยอดต่อ ledger + account + period · Post แล้วแก้ไม่ได้ | เพิ่ม **copy journal** · ต้องออกแบบให้ post ย้อนงวด/ปีปรับยอดยกมาถูก · AutoPost ไว้รอบหลัง |
| Reverse | Reversal period (บังคับ), method: สลับ Dr/Cr (ค่าเริ่มต้น) หรือ เปลี่ยนเครื่องหมาย · reverse ได้ครั้งเดียว, reversal ของ reversal ทำไม่ได้, งวดปลายทางต้อง Open/Future · reversal อยู่ใน batch ใหม่ชื่อขึ้นต้น "Reverses" · **Reversal criteria set** ต่อ category: None / Reverse automatically / Reverse and post automatically · AutoReverse รันตอนเปิดงวดได้ [4][9] | สลับ Dr/Cr, ครั้งเดียว, auto-reverse ต่อ category | เพิ่มวิธี "เปลี่ยนเครื่องหมาย" (ไม่จำเป็นรอบแรก) · เพิ่มตัวเลือก "reverse and post automatically" |
| งวดบัญชี | สถานะ Never opened / Future enterable / Open / Closed / Permanently closed · ledger ตั้งจำนวนงวด future ได้ 0–999 (คีย์ได้แต่ Post ไม่ได้) [7] · ปฏิทินมี period frequency และ **adjusting period frequency** (ไม่มี / 1–2 งวดปลายปี / ทุกไตรมาส) ค่าเริ่มต้นไม่มี · เปลี่ยนยากหลังเปิดงวดแล้ว [8] | ticket 04 | ตอบประเด็นงวด 13/14 ใน ticket 01: ให้ตั้งค่าแบบ Fusion (none / 1 / 2 งวดปลายปี) |
| ปิดงวด GL | ตัวเลือก "ห้ามปิด GL ถ้า subledger ยังเปิด" ตรวจทั้งสถานะงวดของ AP/AR/FA/Cost และรายการที่ยังไม่โอน/ไม่ post [11] | ticket 33 (subledger ปิดก่อน GL ตาม 04) | ตรงกัน ทำเป็นกฎบังคับ ไม่ใช่ตัวเลือก |
| ผังบัญชี | segment + value set (ใช้แบบ independent) · label บังคับ: **primary balancing** และ **natural account**; ไม่บังคับ: cost center, intercompany · ตัวอย่าง segment: company, cost center, account, product, location ฯลฯ [12] | ticket 06 | ใช้ label แบบ Fusion: Company (balancing) + Natural account (บังคับ) + Cost center ฯลฯ → ข้อเสนอสำหรับ ticket 01 |
| Cross-validation | กฎ condition + validation กันการสร้าง combination ที่ไม่ควรมี บังคับตอนสร้าง combination ใหม่เท่านั้น combination เดิมไม่กระทบ ต้องปิดเองถ้าไม่ต้องการ [13] | ticket 06 | ตรงกัน |
| Ledger options | first open period, future periods, retained earnings account (บังคับ, ไม่ควรเปลี่ยน), suspense (เลือกได้), rounding account, balancing thresholds, enable approval, AutoReverse after open period [7] | ticket 04/06/12 | เรา **ไม่ใช้ suspense** (Journal ต้อง balance จริง) · ต้องมี retained earnings account ต่อ ledger สำหรับปิดปี (ticket 33) |
| Spreadsheet upload | Excel add-in มีแผ่น Single Journal / Multiple Journals · กด Submit แล้วตรวจเบื้องต้น ผลใน status viewer · ตัวเลือกอัปโหลด: Save to interface / Import / **Import and post (ค่าเริ่มต้น)** [14] · **ถ้ามี Journal ใดในแผ่นไม่ balance จะไม่อัปโหลดเลยทั้งแผ่น** · จัดกลุ่มเป็น Journal ตาม batch name/description, source, journal name/description, ledger, category [15] · import ผิดไปที่ corrections spreadsheet แก้แล้ว import ใหม่ [16] | template ไม่ใช้ add-in, ทั้งไฟล์ผ่านหรือไม่ผ่าน, จัดกลุ่มด้วย journal_key | ตรงแนวคิด · เพิ่มตัวเลือกหลังนำเข้า "import and post" ตามสิทธิ์ (ticket 36) |
| Journal import (interface) | subledger โหลดเข้า GL interface → Import Journals → Post · ตรวจ cross-validation เมื่อสร้าง combination ใหม่ · งวดต้อง Open/Future [16] | SLA (ticket 37) เขียน Journal ตรงใน transaction เดียว ไม่ผ่าน interface | ต่างโดยตั้งใจ (ADR-0001: ไม่มีขั้นกลางที่ค้างได้) |
| วงจรปลายเดือน | เปิดงวด → คีย์/นำเข้า → recurring/allocation → ตรวจ → post → reverse → revalue/translate → consolidate → รายงาน → ปิดและเปิดงวดถัดไป [17] | เหมือนกัน ยกเว้น revalue/translate/consolidate | นอกขอบเขตตาม 01 (THB เดียว, ไม่ consolidate) |

## สิ่งที่ควรเพิ่มใน ticket จากการอ่านครั้งนี้
- ticket 12: control total, approval status แยกฟิลด์, withdraw, copy journal, post ย้อนงวด/ย้อนปีปรับยอดยกมา
- ticket 04: adjusting period frequency แบบ Fusion, จำนวนงวด future enterable ต่อ ledger
- ticket 06: segment label (balancing, natural account บังคับ), cross-validation rule แบบ condition/validation
- ticket 36: ตัวเลือก import / import and post
