# Fusion อ้างอิง: Receivables (AR) — Credit to Cash

อ่านจาก "Using Receivables Credit to Cash" รุ่น 26D (สรุปด้วยคำของเรา) · ใช้กับ ticket [25](../issues/25-billing-ar-invoice.md), [26](../issues/26-receipts-memos-returns.md), [27](../issues/27-collection.md)

## ตาราง: Fusion ทำอย่างไร → เราทำอย่างไร

| หัวข้อ | Fusion | ระบบเรา (ticket) | ต่าง / ต้องตัดสินใจ |
| --- | --- | --- | --- |
| สถานะ Invoice | Incomplete (ร่าง แก้ได้) → Complete · กลับเป็น Incomplete ไม่ได้ถ้า: ชำระครบแล้ว, ลงบัญชีแล้ว, **พิมพ์แล้ว**, มีการรับชำระ apply อยู่, หรือใช้เลขที่เอกสารเรียงตามวันที่แล้ว (กันเลขขาดช่วง) [1] | post invoice (25) | เพิ่มสถานะ Incomplete/Complete และกฎ "พิมพ์แล้ว/มีเลขแล้วย้อนไม่ได้" — สำคัญสำหรับใบกำกับภาษีไทยที่ห้ามเลขขาดช่วง |
| สร้าง Invoice จากระบบอื่น | **AutoInvoice**: นำเข้า → ตรวจรายบรรทัด → **จัดกลุ่มเป็น invoice ตาม grouping rule** (กำหนดจาก source → customer site → profile → system option) + line ordering rule → ตรวจ header → โอนเข้า AR · บรรทัดที่ผิดค้างใน interface พร้อมข้อผิดพลาด ส่วนที่ผ่านโอนเข้าได้ [5] | billing จาก shipment (25), รวมบิลตาม P02 | P02 (รวม shipment เมื่อ company/OU, bill-to, currency, terms ตรงกัน) คือ **grouping rule** แบบ Fusion → ทำเป็นกฎที่ตั้งค่าได้ต่อ customer site · Fusion ยอมให้ผ่านบางส่วน ของเราใน O2C ทำใน transaction เดียวจึงไม่มีปัญหานี้ |
| รับชำระ (apply) | receipt/credit memo หนึ่งใบตัดได้หลายรายการ บางส่วนได้ · ยอดเริ่มต้น = ยอดค้างหรือยอดยังไม่ apply แล้วแต่อันไหนน้อยกว่า · ตัดหนี้ข้ามลูกค้าได้เฉพาะเมื่อเปิดตัวเลือกหรือมีความสัมพันธ์ pay any / pay below · **unidentified receipt** (ยังไม่รู้ลูกค้า) apply ไม่ได้จนระบุลูกค้า · on-account credit memo ใช้กับ transaction และ refund เท่านั้น [2] | receipt application (26) | เพิ่มสถานะ receipt **unidentified / unapplied / on-account / applied** และกฎตัดหนี้ข้ามลูกค้า (ปิดไว้เป็นค่าเริ่มต้น) |
| Adjustment | ต้องอนุมัติตามวงเงินของผู้อนุมัติ · สถานะ Pending approval → More research → Approved / Rejected · post ได้เฉพาะ Approved · กลับ adjustment ด้วยการสร้างใหม่เครื่องหมายตรงข้าม [3] | ยังไม่มี (มี credit/debit memo) | เพิ่ม **AR adjustment** (ตัดหนี้สูญเล็กน้อย, ปรับเศษ) ผ่าน workflow (ticket 03) ใน ticket 26 |
| Dispute | ข้อโต้แย้งต้องอนุมัติ อนุมัติแล้วสร้าง **credit memo** ไป apply กับ invoice ที่โต้แย้ง ยอดค้างจึงลด [4] | dispute ไม่ลดหนี้ (27) | ตรงกับของเรา: dispute ไม่เปลี่ยนยอดจนกว่าจะออก credit memo ที่อนุมัติแล้ว |
| Dunning | ส่งหนังสือทวงถามอัตโนมัติด้วย template (อีเมล/แฟกซ์/พิมพ์), ยกเว้นลูกค้าตาม profile, มอบหมายการติดตามให้ collector, เก็บประวัติ [6] | collection worklist (27) | เพิ่ม **หนังสือทวงถาม** (พิมพ์/PDF) รอบแรก ส่งอีเมลจริงอยู่นอกขอบเขต (D03) |
| กระทบยอดและรายงาน | Transaction register, Applied/Unapplied receipts register, Aging by GL account, **AR to GL reconciliation** [7] | aging (26) | เพิ่ม register และกระทบยอด AR–GL ใน ticket 26/33 |

## สิ่งที่ควรเพิ่มใน ticket จากการอ่านครั้งนี้
- ticket 25: สถานะ Incomplete/Complete, กฎห้ามย้อนเมื่อพิมพ์/มีเลขแล้ว, grouping rule ตั้งค่าได้ต่อ customer site
- ticket 26: สถานะ receipt (unidentified/unapplied/on-account), AR adjustment พร้อมอนุมัติ, registers
- ticket 27: หนังสือทวงถาม (PDF)
- ticket 33: กระทบยอด AR–GL
